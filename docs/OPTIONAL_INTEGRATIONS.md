# Optional integrations and activation

Implementation support and a verified production connection are separate states. Forecasting, SAP and order dispatch are disabled by default. No production provider, SAP business mapping or workspace provisioning is currently approved. Descriptive charts, maps, review evidence and the 3D camera do not need a forecast provider.

| Adapter | Implemented support | Activation requirements |
| --- | --- | --- |
| Forecast | Bounded source-observation requests, strict matching provider/product/date/unit/snapshot evidence, persisted workspace runs | `FORECAST_ENABLED=true`, approved HTTPS `FORECAST_PROVIDER_URL`, `FORECAST_PROVIDER_NAME`, optional `FORECAST_PROVIDER_TOKEN_FILE`, and authorized actual observations |
| SAP | Read-only OData `$metadata` receipt: bounded XML envelope, SHA-256, size and observation time; authenticated admin/engineer and explicit workspace allowlist | `SAP_ENABLED=true`, approved HTTPS service root `SAP_SERVICE_URL`, `SAP_BEARER_TOKEN_FILE`, `SAP_WORKSPACE_ALLOWLIST` containing approved UUIDs |
| Order dispatch | Atomic order/outbox, stable message identity, bounded retries and preserved disabled/pending/sending/failed/sent state; Azure Service Bus transport | `ServiceBus__Enabled=true`, approved `ServiceBus__OrderQueueName`, `ServiceBus__ConnectionStringFile` |
| Operational mail | Durable opt-in review notifications with bounded retry | Separate `EMAIL_NOTIFICATIONS_ENABLED=true`, configured existing mail transport, and explicit per-user/workspace opt-in |

Credential references are **server-side absolute file paths**, never frontend variables or request parameters. Mount existing secret-store files read-only into the container, readable by its application UID, and restrict their host permissions. Node references permit one nonempty value up to 16 KiB. Supply Chain uses a bounded connection-string reference. Existing server environment values remain supported, but setting both inline and file sources is rejected. Do not place credentials in source control, URLs, browser storage, screenshots or logs. Optional disabled adapters make no provider requests and do not require credentials.

Explicitly enabled adapters fail startup validation if required settings are missing or invalid. HTTPS endpoint credentials/query strings, ambiguous credentials and invalid workspace scopes are rejected. Responses and errors omit credential values. File custody and runtime read permissions must be checked before activation; a configured state is not connectivity evidence.

SAP support is **service metadata inspection**, not business synchronization, order fulfillment or an inferred tenant mapping. `GET /api/operations/integrations/sap/metadata` requests only the fixed operator-configured service's `$metadata`; redirects, HTML fallbacks, XML entity declarations and bodies over 1 MiB are rejected. It returns a receipt rather than raw XML or business records. Unsupported/unauthorized workspaces are denied. Any future business synchronization needs a separately reviewed SAP entity contract, ownership mapping and idempotency/reconciliation plan. [SAP documents the service metadata resource](https://www.sap.com/Protocols/SAPData).

Service Bus activation validates the credential structure and any entity-scoped queue against the selected queue using the [Azure SDK parser](https://learn.microsoft.com/en-us/dotnet/api/azure.messaging.servicebus.servicebusconnectionstringproperties.parse). No namespace or queue is created. An unavailable broker leaves durable evidence; after bounded attempts a row is failed, not falsely marked sent. `GET /supply-chain/api/v1/orders/transport` reports the current organization's actual state counts. `sent` means transport accepted, not fulfilled. Preserve the same MessageId during reviewed recovery; see [recovery](RECOVERY.md).

The Integrations UI distinguishes **Not configured**, **Configured**, **Not authorized**, and **Unavailable**. An unreadable source does not become Not configured. SAP metadata checks are manual; no provider is polled or connected merely by opening the dashboard. Demo graphics and values remain explicitly labelled demonstrations. Camera rotation moves only the view, pauses on manual interaction and honors reduced-motion preferences.

Activation requires approved service identities/endpoints and credentials in the existing secret mechanism, plus explicit workspace authorization and source observations where relevant. Test against an isolated provider/transport double first; then separately approve real provider checks. No production records, memberships, external resources or paid subscriptions are created by this implementation.
