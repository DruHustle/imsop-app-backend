# Supported release path

The supported target is the existing ARM64 Software Engineering Backend VM, independent of Onesa and sibling services. See [Oracle runbook](../deploy/oracle/README.md). Kubernetes manifests are unsupported historical examples and the active deployment workflow is retired. Terraform/Azure designs do not authorize provisioning.

Build and test a clean committed backend with explicit `linux/arm64` (CI publishing produces amd64/arm64). Supply `APP_REVISION` equal to the exact source SHA. Check image architecture, OCI manifest digest, OCI revision label, `/version` and `/ready`. Generate a release manifest using `node scripts/release-manifest.mjs FRONTEND_SHA BACKEND_SHA OCI_MANIFEST_DIGEST`. A local image qualification receipt is not a production release receipt.

Before production: confirm the provider backup/restore policy, perform read-only ownership preflight, approve explicit provisioning, prepare separate migration credentials, configure the recovery encryption key and existing email/webhook secrets in the existing secret mechanism. Never print them. Apply Node forward migrations and .NET EF migrations under their separate owners with runtime auto-migration disabled. Existing unassigned data stays inaccessible. Provision confirmed internal users/data from reviewed evidence. Require fresh login.

Deploy the compatible backend first, verify session/cookie/role/scope/report contracts and installed/runtime SHA against the manifest, then release the dependent frontend. Preserve the existing root-base first-party Vercel proxy. All rollout/merge steps require the existing production authorization; none was performed by this task. Do not infer running SHA from green CI or a healthy probe.

Rollback: retain the previous compatible image digest and exact installed Compose overrides. In an isolated environment replace only the IMSOP image, wait for readiness/version, then restore the candidate image. Preserve schema and data; do not use destructive reverse migrations. The old pre-boundary application is not an acceptable security rollback if it exposes quarantined data. Repair forward or use a previously qualified scoped image. Never restart sibling applications, expose internal ports or duplicate workers.
